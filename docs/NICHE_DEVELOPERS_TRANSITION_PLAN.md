# План перехода Sensify в нишу Developers

**Цель:** позиционирование «AI-ассистент для разработчиков» (GitHub, Reddit, документация, приватность), упрощение продукта за счёт отказа от универсального «для всех».

**Опорный документ:** `MARKET_ANALYSIS_SENSIFY.md` (март 2026).

### Статус (v1.9.3)

Единая таблица **реализовано / в работе / бэклог** — **[STATUS.md](./STATUS.md)**.  
По продукту: фазы **0–4** в основном закрыты (мета, UI под dev, GitHub/Reddit, доки); **фаза 5** (контент, опционально `/developers`) — ongoing. Рекомендации §2 (спрятать Substack / «Ещё» для YouTube и Notion) **не все внедрены** — источники пока в полном наборе; при необходимости вернуться к §2 перед следующим редизайном вкладок.

## 2. Источники: что оставить, что убрать, что объединить

### 2.1 Ядро (обязательно оставить, вынести вперёд в UI)

| Источник | Зачем dev-нише |
|----------|----------------|
| **GitHub** | README, issues, discussions, PR-контекст |
| **Reddit** | r/golang, r/ExperiencedDevs, обсуждения |
| **Telegram** | публичные dev-каналы |
| **Ссылка (URL)** | MDN, RFC, блоги, доки, Substack/Medium по URL |
| **RSS** | трекинг блогов и релизов |
| **PDF** | спеки, whitepapers, статьи |
| **Текст** | логи, фрагменты кода, paste |

### 2.2 Убрать или спрятать (лишнее для узкой ниши)

| Элемент | Рекомендация | Почему |
|---------|--------------|--------|
| **Отдельная вкладка Substack** | **Убрать** | Тот же пайплайн, что у URL (`fetchUrlContent`). Достаточно вставить URL в «Ссылку». |
| **Вкладка Notion** | **Вариант A:** убрать из главного ряда · **Вариант B:** оставить | A — проще продукт. B — многие dev ведут заметки в Notion; тогда оставить последней в списке или в блоке «Ещё». |
| **YouTube** | **Вариант A:** убрать · **Вариант B:** оставить во «Втором ряду» / «Ещё» | Для ниши полезны доклады; для фокуса «только текст и репозитории» — убрать. |

**Итоговая рекомендация фазы 1 (жёсткая чистка):**

- Убрать: **Substack** как тип `InputType` и отдельную вкладку.
- Оставить **YouTube** и **Notion** только если не готовы резать функциональность; иначе перенести в раздел «Дополнительные источники» (один collapsible) или убрать в фазе 2.

### 2.3 Порядок вкладок после чистки (пример)

1. GitHub  
2. Reddit  
3. Ссылка  
4. Telegram  
5. RSS  
6. PDF  
7. Текст  
8. *(опционально)* YouTube, Notion — в конце или в «Ещё»

## 3. Пресеты извлечения

### 3.1 Убрать / заменить

| Текущий пресет | Действие |
|----------------|----------|
| **Наука (science)** | Убрать или заменить на **Research** (статьи, RFC, PDF) |
| **Бизнес (business)** | **Убрать** |
| **Обучение (education)** | **Убрать** (или слить с «Конспект» → переименовать в **Technical notes**) |
| **Конспект (study)** | Переименовать в **Technical notes** / «Заметки по доке» |
| **Статья (article)** | Оставить как **Thread / Discussion** (обсуждения, посты) |
| **Action items** | Оставить — задачи из issues/тредов |
| **По умолчанию** | Оставить |

### 3.2 Добавить (новые типы в `ExtractionPreset`)

- **`technical_docs`** — API, README, официальные гайды: команды, параметры, примеры.  
- **`discussion`** — Reddit, GitHub Discussions: позиции, контраргументы, итог.  
- **`release_notes`** — changelog, релизы: breaking changes, миграция.

*Требует:* обновление `src/types/index.ts`, списков пресетов в `input-panel`, `settings-dialog`, `output-panel`, `src/lib/extract/prompts.ts` (`presetInstructions`), дефолты в `store`, миграция старых значений в истории (маппинг `science` → `research` и т.д., если нужно).

## 9. Данные и обратная совместимость

- **История / БД:** старые записи с `sourceType: "substack"` отображать как **«Ссылка»** или **«Substack (архив)»** в UI.  
- **localStorage (Zustand):** при смене дефолтной вкладки учесть, что у пользователя мог сохраниться `substack` — миграция в `url` при гидрации.  
- **API extract:** на переходный период принимать `substack` как алиас к `url` (лог в warning), потом убрать.
