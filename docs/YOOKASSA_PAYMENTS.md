# Настройка платежей ЮKassa (Sensify)

В приложении уже реализованы: создание платежа (`POST /api/payments/create`), редирект на оплату, webhook `POST /api/webhooks/yookassa`, запись в `PaymentLog`, продление `Subscription`, страница `/premium`, журнал в админке (`GET /api/admin/payments`).

Ниже — что нужно сделать **в личном кабинете ЮKassa и в окружении**, чтобы всё заработало.

---

## 1. Регистрация и магазин

1. Зарегистрируйтесь в [ЮKassa](https://yookassa.ru/) и подключите магазин (ИП / ООО или самозанятый — по правилам ЮKassa).
2. В разделе **Настройки → Ключи API** возьмите:
   - **shopId** (идентификатор магазина);
   - **Секретный ключ** (`live_...` для боя, `test_...` для тестов).

---

## 2. Переменные окружения

Скопируйте в `.env.local` (локально) или в **Vercel → Project → Settings → Environment Variables**:

| Переменная | Описание |
|------------|----------|
| `YOOKASSA_SHOP_ID` | ID магазина из личного кабинета |
| `YOOKASSA_SECRET_KEY` | Секретный ключ (`test_` или `live_`) |
| `YOOKASSA_WEBHOOK_IP_CHECK` | `1` (по умолчанию) — проверять IP webhook; **`0`** — отключить (только для отладки / туннеля) |

Дополнительно для авторизации и редиректов:

| Переменная | Описание |
|------------|----------|
| `NEXTAUTH_URL` | Публичный URL сайта, например `https://your-app.vercel.app` (без слэша в конце). Нужен для корректной работы NextAuth и ссылок возврата. |
| `AUTH_SECRET` | Секрет сессий (≥ 32 символов). |

Без `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` API вернёт **503** с текстом «Платежи не настроены».

---

## 3. Webhook (обязательно для активации премиума)

После оплаты ЮKassa шлёт уведомление на ваш URL. Его должен обрабатывать бэкенд — иначе деньги спишутся, а подписка в БД не обновится.

1. В личном кабинете ЮKassa: **Интеграция → HTTP-уведомления** (или аналог для вашего типа подключения).
2. URL уведомлений:  
   **`https://<ваш-домен>/api/webhooks/yookassa`**
3. События: достаточно **`payment.succeeded`** (так обрабатывает текущий код).

**Локальная разработка:** публичный URL нужен снаружи (ngrok, Cloudflare Tunnel и т.п.). Временно можно выставить `YOOKASSA_WEBHOOK_IP_CHECK=0`, иначе проверка IP отсечёт запросы не с официальных адресов ЮKassa (см. `src/lib/yookassa-ip.ts`).

**Production:** оставьте проверку IP включённой (`1` или не задавайте переменную).

---

## 4. Поток оплаты

1. Пользователь авторизован → `/premium` → «Оформить» → `POST /api/payments/create` с `{ "plan": "monthly" | "yearly" }`.
2. Ответ: `confirmationUrl` → редирект на страницу оплаты ЮKassa.
3. `return_url` в платеже: **`{origin}/premium?success=1`** — после оплаты пользователь возвращается на премиум-страницу (тост «Оплата прошла успешно»).
4. Параллельно ЮKassa вызывает **`POST /api/webhooks/yookassa`** → обновляются `Subscription` и `PaymentLog`.

Суммы и описания зашиты в `src/app/api/payments/create/route.ts` (`PLANS`: месяц / год в RUB). При необходимости измените там же.

---

## 5. Проверка после настройки

1. Тестовый ключ `test_...`, тестовая карта из [документации ЮKassa](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing).
2. Убедитесь, что webhook доходит (логи Vercel / сервера, записи в таблице `payment_logs` в БД).
3. В админке (**журнал платежей**) должны появляться строки с `yookassaPaymentId`, email, планом.
4. **`GET /api/health`**: **`paymentsConfigured`**, а также **`databaseBackend`**, **`rateLimitDistributed`** — см. [`DATABASE_PRODUCTION.md`](./DATABASE_PRODUCTION.md).

---

## 6. Типичные проблемы

| Симптом | Что проверить |
|---------|----------------|
| «Платежи не настроены» | Заданы ли `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` на том же окружении, где крутится приложение. |
| Оплатил, премиума нет | Webhook URL, HTTPS, доступность `/api/webhooks/yookassa`; при 403 в логах — IP-проверка (`YOOKASSA_WEBHOOK_IP_CHECK`). |
| 401/ошибка создания платежа | Верность shopId и secret, тест vs live окружение. |
| Редирект после оплаты «ломается» | `NEXTAUTH_URL` и фактический домен совпадают с тем, что в браузере. |

---

## 7. Безопасность

- Секретный ключ только в env, не в репозитории.
- В продакшене не отключайте проверку IP webhook без веской причины.
- Подробнее про премиум и клиентский экспорт: [`SECURITY_PREMIUM.md`](./SECURITY_PREMIUM.md).
