# Премиум: границы защиты (честный пользователь vs атакующий)

## Где подписка проверяется на сервере (надёжно)

| Функция | Проверка |
|---------|-----------|
| Лимиты извлечений | `POST /api/extract` — подсчёт в БД, премиум снимает дневной лимит |
| Отправка в Notion | `POST /api/integrations/notion/push` — сессия + `premiumUntil` в БД |
| Статус в UI | `GET /api/user/premium` — только для отображения и повторной проверки перед действием |

Обход через подмену ответа `fetch` в консоли возможен только на **клиенте**; серверные маршруты выше не доверяют телу клиента для выдачи премиума.

## Где защита только в интерфейсе (ограничения браузера)

Сборка **Obsidian / Notion JSON / Markdown / PDF** и скачивание выполняются **в браузере**: данные извлечения уже есть у пользователя в памяти после успешного `POST /api/extract`. Технически подкованный пользователь может вызвать те же функции из консоли.

**Что сделано в продукте:**

- Перед премиум-экспортом повторный запрос **`/api/user/premium`** (актуальный статус).
- Предпросмотр экспорта без подписки: **фрагмент текста**, блокировки **copy/cut/context menu**, без выделения; с подпиской — полный текст и можно копировать.

**Итог:** для контента, который уже выдан моделью, «железная» коммерческая защита возможна только через **серверный рендер экспорта** (например, PDF только с API после проверки премиума). Это усложняет архитектуру; текущая модель — баланс UX и стоимости.

## Рекомендации на будущее

- Вынести генерацию **PDF** на `POST /api/export/pdf` с проверкой премиума (тело: `resultId` или payload + session).
- Те же **премиум-форматы файлов** при желании — только после оплаты на сервере.
- Продолжать любые **новые** платные интеграции только с проверкой в route handler.
