## 2. Будущая логика

### 2.1 Хранение статуса премиума

**Вариант A (локально):**
```ts
// src/lib/store.ts
isPremium: boolean;  // из localStorage / persist
```

**Вариант B (с бэкендом):**
- API `GET /api/user` или `GET /api/premium/status` возвращает `{ isPremium: boolean }`
- Требуется авторизация (JWT, сессия, email+license)

**Рекомендация:** Начать с A для MVP, затем перейти на B.

### 2.2 Где проверять isPremium

| Место | Действие |
|-------|----------|
| `export-panel.tsx` → `handleExport` | Если `exportFormat` in ['obsidian','notion','markdown'] и `!isPremium` → показать модалку «Оформите Премиум» и редирект на /premium |
| `export-panel.tsx` → карточки форматов | PRO-форматы при `!isPremium` — визуально заблокированы (opacity, lock icon), клик открывает модалку |
| `generateExport` в exporters.ts | Опционально: серверная проверка, если экспорт пойдёт через API |

### 2.3 Ограничения для бесплатных пользователей

- **Бесплатно:** Буфер обмена, Красивый текст
- **Премиум:** Obsidian, Notion, Markdown

При выборе премиум-формата без подписки:
1. Toast: «Этот формат доступен в Премиум»
2. Или модалка с CTA «Перейти к тарифам»

### 2.4 Покупка подписки (будущее)

**Этапы:**
1. Интеграция платёжной системы (Stripe, ЮKassa, etc.)
2. Страница /premium: кнопки «Оформить» → checkout
3. Webhook от платёжки → сохранение в БД: `user_id` + `premium_until`
4. API `/api/premium/status` проверяет `premium_until > now`
5. Frontend: при загрузке приложения запрос статуса, запись `isPremium` в store

**Структура БД (пример):**
```
subscriptions:
  user_id (email / id)
  plan: 'monthly' | 'yearly'
  premium_until: timestamp
  payment_id
```
